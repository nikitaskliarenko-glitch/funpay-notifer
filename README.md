# FunPay Robux watcher

Следит за списком робуксов на `https://funpay.com/chips/99/` и пишет в Telegram,
как только появляется предложение, подходящее под твои пороги.

Веб-приложения нет намеренно. У службы нет ни одного входящего порта: она сама
ходит к FunPay и сама забирает обновления у Telegram. Единственная проверка
доступа — совпадение Telegram user id с `OWNER_ID`. Сообщения от кого угодно
ещё не доходят ни до одного обработчика.

## Как это работает

Раз в 30 секунд служба скачивает страницу списка. Один запрос отдаёт все
примерно 600 предложений сразу, авторизация и JavaScript не нужны, ответ весит
около 49 КБ в сжатом виде. Кука `cy=usd` заставляет FunPay отдавать цены в
долларах.

Сообщение приходит **в момент, когда предложение становится подходящим**. Это
покрывает три случая сразу: появился новый оффер, давний подешевел до твоего
порога, у подходящего появилось наличие. Об одном и том же предложении повторно
пишем, только если цена упала ещё минимум на 5 процентов.

## Команды

| Команда | Что делает |
|---|---|
| `/start` | справка и текущие пороги |
| `/filters` | показать пороги |
| `/set поле значение` | изменить порог, например `/set max_price 0.0075` |
| `/on` | включить поиск и показать, что подходит прямо сейчас |
| `/off` | выключить поиск |
| `/test` | что подходит сейчас, ничего не включая |
| `/status` | когда был последний успешный опрос и что с ним |

## Пороги

| Поле | Смысл | По умолчанию |
|---|---|---|
| `min_stock` | наличие от | 1 |
| `min_stars` | звёзды от, 1 до 5, либо `нет` | 4 |
| `min_reviews` | отзывов у продавца от | 100 |
| `max_price` | цена за 1 робукс в долларах, не выше | 0.0080 |
| `min_tenure_months` | на сайте от, месяцев | 12 |
| `only_online` | только продавцы онлайн, `да` или `нет` | нет |

### Почему по умолчанию 4 звезды, а не 5

В общем списке FunPay округляет рейтинг **вниз** до целого. У продавца с
настоящим рейтингом 4.8 в списке стоит 4 звезды. Порог 5 отсёк бы его вместе с
большинством хороших продавцов, поэтому по умолчанию стоит 4. Точный рейтинг
виден только в профиле продавца, и служба туда не ходит.

## Запуск

Нужен Python 3.10 или новее. Проверить системный:

```bash
/usr/bin/python3 --version
```

Забрать код и собрать окружение:

```bash
sudo mkdir -p /opt/funpay-watch
sudo chown $USER:$USER /opt/funpay-watch
git clone <репозиторий> /opt/funpay-watch
cd /opt/funpay-watch

sudo apt install -y python3-venv
/usr/bin/python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

Вызов `python -m pip` вместо просто `pip` тоже не случаен. На Ubuntu файл
`.venv/bin/pip` иногда не создаётся, хотя сам pip установлен, и короткая
команда падает с `No such file or directory`. Через модуль работает всегда.

Путь `/usr/bin/python3` указан полностью не для красоты. Если на сервере стоит
pyenv, короткое `python3` подсунет интерпретатор из `/root/.pyenv`, а туда
пользователю службы хода нет: домашняя папка root закрыта правами `drwx------`.
Служба тогда не стартует с ошибкой `203/EXEC`.

Настройки. Токен берётся у `@BotFather`, свой user id — у `@userinfobot`:

```bash
cp .env.example .env
nano .env
```

Разовая проверка. Бот должен ответить на `/start` в Telegram. Останови
через `Ctrl+C`, иначе вторая копия не запустится: замок на базе не пустит.

```bash
.venv/bin/python -m funpay_watch
```

Как служба:

```bash
sudo useradd --system --home /opt/funpay-watch funpay
sudo chown -R funpay:funpay /opt/funpay-watch
sudo cp funpay-watch.service /etc/systemd/system/
sudo systemctl enable --now funpay-watch
journalctl -u funpay-watch -n 20
```

Передача прав идёт **после** сборки окружения. Соберёшь под root и забудешь
передать — служба не прочитает свои же файлы.

В журнале первой строкой будет путь к базе. Убедись, что он ведёт
в `/opt/funpay-watch`, и задавай пороги через `/set`.

## Тесты

```bash
.venv/bin/python -m pip install -r requirements-dev.txt

```

Разбор проверяется на сохранённом снимке живой страницы в
`tests/fixtures/chips99.html`. Сеть тестам не нужна.

## Что служба делает, чтобы не мешать сайту и не сломаться молча

- Интервал опроса гуляет на плюс-минус 20 процентов, сессия и куки живут между
  запросами: так поведение ближе к обычному браузеру.
- На ответы 403, 429 и 503 включается отступление от минуты до пятнадцати,
  о первом сбое и о восстановлении приходит по одному сообщению.
- Если разбор дал ноль предложений или цены пришли не в долларах, цикл считается
  неудачным и состояние не обновляется. Это ловит и смену вёрстки, и потерю куки
  валюты, при которой рублёвые цены молча прошли бы долларовый порог.
- Если под пороги за один цикл попало больше 20 предложений, показываются самые
  дешёвые, а об остальных приходит одна строка с советом ужесточить пороги.

## Только одна копия на базу

При старте служба берёт замок рядом с файлом базы и держит его до остановки.
Вторая копия на той же базе получит отказ и не запустится.

Проверка не формальная. Две копии на разных базах ведут себя особенно скверно:
команды достаются одной, а рассылку ведёт другая, со своими порогами. Снаружи
это выглядит как поломка фильтров, хотя пороги сохраняются правильно. Путь
к базе служба пишет в журнал первой же строкой, чтобы такое было видно сразу.

Если понадобится, найти лишние копии и базы можно так:

```bash
ps aux | grep "[f]unpay_watch"
find / -name "funpay_watch.db*" 2>/dev/null
```

Путь из `DB_PATH` разворачивается в абсолютный. Относительный создавал бы базу
там, откуда запущен процесс, и копии из разных папок разошлись бы по разным
базам незаметно для владельца.

## Известные ограничения

- Звёзды берутся округлёнными из списка, точный рейтинг из профиля не читается.
- Минимальный заказ продавца известен только на странице предложения, поэтому он
  дописывается в уже отправленное сообщение и фильтром не является. Разброс там
  большой, от единиц до тысяч, и он меняется в реальном времени.
- Способ передачи не фильтруется, он просто указан в сообщении. Game Pass идёт
  5 дней и стоит дешевле мгновенных способов.
